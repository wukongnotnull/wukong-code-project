# 完成前验证

- 声称完成、通过或已修复之前，必须在当前改动上实际运行能证明这一点的命令，读完输出、确认退出码和失败数，再下结论。“应该能过”或之前的运行结果不算证据；代码或 HEAD 变了就要重跑。
- 检查命令以项目自己的说明为准（`AGENTS.md`、`CLAUDE.md`、README、CI 配置）：测试、类型检查、lint、构建都要覆盖。在 PR 或回复中写出命令、结果和数量。
- “Bug 已修复”要用原始症状验证；“需求已满足”要逐条对照需求。没运行的检查明确写“未验证”，缺少的工具如实说明。
- 本地验证不能代替 CI，CI 是最后一道关卡。
- 收到评审意见先核实是否成立，再修改，或说明不改的理由。
